# 高教杯结构化论文写作

## 阶段合同（机器接口）

- phase_id: 09-cumcm-writing；display_name: 结构化论文写作；owner_agent: writing-agent。
- entry_conditions: G2.status=CONFIRMED；08 模板锁定；结果和引用证据可追溯。
- inputs: G1/G2、ANALYSIS_MODELING_REPORT、RESULTS_INDEX、结果/图表、template_lock 和题面。
- outputs: paper/PAPER_BLUEPRINT.md、paper/正文 section、摘要、结论、引用索引。
- exit_conditions: 每问 A-E 功能齐全且按题型自适应标题；数字和图表全部绑定 result_id；phase_result=READY_FOR_LATEX。
- failure_return: 事实/结果返回 05/06；模板返回 08；正文组织返回 09；不自行编译。
- writable_paths: paper/PAPER_BLUEPRINT.md、paper/sections/、paper/abstract/、references/REFERENCE_INDEX.csv。
- read_only_paths: code/、results/、figures/、template_lock、G1/G2 和题面。
- invalidates: 正文事实、公式、数字、引用或结构变化使 10、11、12、13 失效。
- user_gate: false。
## 本地多智能体合同
- owner_agent：writing-agent；
- 只消费 G1/G2 已锁定的模型和当前结果；
- 用户锁定文本优先，禁止未经授权自行扩写；
- 先生成 PAPER_BLUEPRINT，再生成正文；
- 退出状态：embedded、REVISE 或 BLOCKED。

本 skill 是国赛唯一主写作入口。它承接 `04-cumcm-modeling`、`05-cumcm-coding-visual` 和 `07-cumcm-drawio`，把已锁定的真实模型、结果、表格、图表和代码组织成可审查的中文 LaTeX 论文。不得编造数值、图表、引用或模型结果；不得在结果资产未盘点时开始写作。


如果项目已经有用户确认的模板工程，复制该工程到独立 `paper/` 目录并保留类文件；不得改用通用 `ctexart` 或其他比赛模板。复制后把模板 ID、`cumcmthesis.cls`/`main.tex` 哈希和实际路径写入 `run_manifest.json` 或等价元数据；哈希不一致时停止写作并报告。默认使用中文 XeLaTeX，连续编译至少两遍。不得在写作阶段修改 `cumcmthesis.cls`。

- 证据包完整；
- 主要结果表、主要结果图和检验证据已生成；

- 所有正文数字可回到结果文件；

缺任一项，回到责任阶段，不直接写简略论文。若建模报告只有候选模型而没有用户确认后的锁定模型，退回 `04-cumcm-modeling`；若 MVP/AI 评审未通过或没有用户 G2 确认，退回 `06-cumcm-result-mvp`；写作阶段不得重新选择或替换模型。

## 写作蓝图门禁

在创建或覆盖任何正文 `.tex` 文件前，先在论文工程中生成 `PAPER_BLUEPRINT.md`。蓝图不是论文正文，而是逐问写作接口；每个顶层问题必须填写：

```text
问题目标与题意输出
输入数据、变量和前问依赖
已确认主模型、透明基线和允许的敏感性方法
A 具体分析：任务、难点、步骤和衔接
B 模型准备：数据问题、处理动作和处理后输入
C 算法选择：已确认模型的适用性、对照方法和未选理由
D 模型建立与求解：公式、符号、约束、算法、结果和验证
E 问题小结：定量回答、适用边界和传递到下一问的输出
核心 result_id、表、图、引用和目标章节
```

蓝图必须与 `ANALYSIS_MODELING_REPORT.md`、`DECISIONS.md` 和 `RESULTS_INDEX.csv` 一致。蓝图必须为每个拟写小节登记 `function_tags`：`A`（具体分析）、`B`（模型准备）、`C`（算法选择）、`D`（模型建立/求解/结果/验证）、`E`（问题小结）。蓝图缺少 A–E 任一功能、锁定模型、核心结果或验证证据时，停止写作并退回责任阶段；不得用泛化文字补齐空缺。蓝图确认后再生成正文，正文中不得出现蓝图占位符。

## 固定论文结构

入口文件按实际问题数组织；模板中的四问输入仅是基准工程，必须按题面实际问题数增删：

```text
摘要与关键词
一、问题重述
二、模型假设
三、符号说明
四、问题一的建模与求解
五、问题二的建模与求解
……
灵敏度分析或稳健性检验
模型评价与推广
参考文献（独立起页）
附录（再次独立起页）
```

每个问题的一级标题必须是“问题 X 的建模与求解”，随后先写总起段；正文必须完整实现 A–E 五个论证功能，但不要求标题机械写成“问题分析/模型准备/算法选择/模型建立与求解/问题 X 小结”。具体标题、层级和功能组合必须依据题型、数据结构和模型链自适应生成，例如“数据与收益口径”可覆盖 B，“决策变量与约束体系”可覆盖 B+D，“结果回代与稳健性分析”可覆盖 D，“问题 X 结论”覆盖 E。A–E 可分散在多个小节，也可由一个小节承担多个功能，但必须在 `PAPER_BLUEPRINT.md` 的 `function_tags` 中可追踪。功能映射到模板的 section/subsection/subsubsection 层级时，不得绕过模板定义自行改字号、边距或编号。

## 每问丰满证据契约

每问正文不得退化为“几段文字 + 一个公式 + 一张图”。至少写入：

1. 问题分析和与前问的关系；
2. 数据处理、缺失/异常/极端值和变量定义；
3. 已确认模型的选择依据、透明基线、成熟对照和未选方法理由（可用紧凑三线表）；
4. 完整数学表达：符号、目标、约束、统计假设或评价指标；
5. 算法/求解步骤和可行性说明；
6. 至少一张主要结果表；
7. 至少一张服务于结论的主要结果图；
8. 有效性、误差、稳健性或敏感性证据；
9. 图表前引入句、图表后现象解释和定量结论；
10. 直接回答题意的问题小结。

若题型不适合某类证据，使用等价证据并在正文或 `DECISIONS.md` 解释，不得制造无意义图表。

写作时必须逐问消费建模报告中的闭环矩阵。每问正文完成前，逐项核对题意输出、用户确认后的锁定模型、关键假设、验证方法、核心 `result_id`、主要表/图或等价证据、论文对象、定量结论和小结回答。缺少一项时，必须退回 `04-cumcm-modeling` 或 `05-cumcm-coding-visual`。写作阶段只能解释已锁定的模型，不得重新进行模型选型。

## A–E 行文规则：功能固定、标题自适应

每个问题按以下论证顺序组织自然段，段落之间必须有因果或承接关系。A–E 是强制论证覆盖协议，不是固定标题协议；写作前先根据题型生成自然标题，再用功能标签审计覆盖。

### A. 具体分析（功能标签 A）

先明确本问要回答的题面任务、输入、输出、评价目标、主要难点及与前问的关系；再用“首先—接着—然后—最后”说明后续处理和求解路线。不要在本节堆叠算法名称或提前罗列最终数字。

### B. 模型准备（功能标签 B）

说明原始数据为何不能直接进入模型，具体交代量纲、方向、编码、缺失、异常、粒度和结构性缺失的处理；说明每项处理改变了什么、保留了什么，以及处理后数据如何进入已确认模型。不能只写“进行了预处理”。

### C. 算法选择（功能标签 C）

承接模型准备，解释 `04-cumcm-modeling` 已确认的主模型为什么适合本题，并列出透明基线或成熟对照；用适用条件、解释性、验证性、复现性和计算成本说明取舍，明确未选方法及原因。不得在本节另行替换锁定模型，不得以“模型较先进”作为唯一理由。

### D. 模型建立与求解（功能标签 D）

先说明公式要解决的目标，再给出变量、参数、单位、目标函数、约束、统计假设或评价指标；公式后逐项解释符号和条件。随后说明与真实代码一致的求解步骤、停止条件、可行性或误差检验，再呈现结果表和图，并在图表后写比较、趋势、数量级和对题意的含义。

### E. 问题小结（功能标签 E）

直接回答本问，不重复模型介绍。至少写出最重要的排序、方案、预测、判定或数值结果，说明结论成立的数据范围和关键约束，并明确本问输出如何传递到下一问；不得引入正文和结果索引中没有的新结论。

不得机械复制统一小标题，也不得用标题灵活掩盖功能缺失。`11-cumcm-verify` 应根据 `PAPER_BLUEPRINT.md` 的 `function_tags` 和正文语义检查 A–E 覆盖，而不是只搜索“问题分析”等固定字符串。

## 段落、结果与语气约束

- 每个核心段落至少完成“目的/动作—依据—结果—解释”中的三项；结果段必须包含定量对象或明确判定，不能用单句空泛总结代替。
- 结果主体使用确定、直接且有边界的表达：`结果表明……`、`比较结果显示……`、`因此选取……`、`由计算得到……`、`在给定约束下……`、`敏感性分析显示……`。
- 将样本范围、因果边界、费用口径、编码不确定性和模型限制集中放在“模型假设”“敏感性分析”“模型评价与推广”，不要在每个结果句后重复自我否定。
- 禁止或慎用：`AI认为`、`可能比较好`、`暂时选择`、`结果仅供参考`、`模型似乎有效`、`大概`、`应该可以`。不得把相关写成因果，把预测概率写成现实发生概率，把相对评分写成绝对质量。
- 丰满度来自完整证据链、解释密度和题意回答，不来自重复背景、堆砌模型名、重复公式、无关图表、空白页或代码凑篇幅。

## 结果覆盖写作

逐行消费 `RESULTS_INDEX.csv`。每个核心结果必须完成：

```text
结果文件 → 表/图编号 → 正文引用 → 现象解释 → 小结使用
```

表格优先使用真实 CSV/JSON 生成的三线表；预测题要展示关键预测明细或可读的分段表；模型选择题要展示候选比较；优化题要展示可行性、最优方案和敏感性；检验题要同时写效应量、区间和显著性。正文中不能出现 `reports/`、`results/`、内部 skill 名称、临时路径或隐藏 AI 状态。

每个结果写入论文后，立即在 `RESULTS_INDEX.csv` 补齐表/图编号、章节、正文引用、现象解释和小结使用，并将状态从 `generated` 更新为 `embedded`。没有正文引用和解释的结果不得标记为 `embedded`。

## 参考文献与引用流程

参考文献必须从 `references/REFERENCE_INDEX.csv` 消费，不得临时凭记忆添加。对每条正文引用：

1. 使用已登记的 `reference_key` 和 `references.bib` 条目；
2. 确保引用支撑对应的模型、定义、算法或判断；
3. 将 `citation_status` 更新为 `used`，填写 `paper_section`；
4. 编译后核对正文引用与参考文献双向一致，没有未定义引用、孤立条目或只列不引的文献。

不得引用外部资料来伪造本题数据、结果或结论；文献只支撑方法依据和讨论背景。

## 摘要契约

中文摘要固定为：

```text
背景与研究价值/总体框架
问题一（独立自然段）
问题二（独立自然段）
……最后一个问题（独立自然段）
三项创新与应用价值
```

每个问题段按“目的—模型—关键处理—核心指标/数值—结论”组织。适度加粗模型名、关键指标和直接结论，不整段加粗。摘要数字必须来自结果索引或结果文件。

摘要生成前先从 `RESULTS_INDEX.csv` 和已确认的建模报告提取每问的主模型、关键处理、核心数字和直接结论，再组织成自然段；不得凭记忆、从旧版本论文复制或用“首先、其次、最后”写成流水账。摘要自检必须满足：每个顶层问题恰有一个独立段落；每段至少出现一个主模型或明确方法链、一个可追溯核心结果和一个直接回答；总体段交代研究对象与模型链；末段概括不超过三项有证据支撑的创新或应用价值。没有结果资产的问题不得在摘要中虚构数字，应回退到写作前门禁。

## 图表与版式

- 数据图来自真实代码，保存 PDF、PNG 和作图数据；
- 图内不放重复大标题，caption 由 LaTeX 负责；
- 默认使用 `[htbp]`，谨慎使用 `[H]`；章节边界可用 `\FloatBarrier`；
- 相关图优先组合为双子图或与结果表组成紧凑论证单元；
- 图表不无理由单独占页，正文不能出现异常大块空白；
- 图表前有引入句，图表后立即解释；
- 中文变量、单位、坐标和图例清楚；
- 表题在表上、图题在图下，优先矢量 PDF。

表格统一优先使用三线表：`\toprule`、`\midrule`、`\bottomrule`，不使用竖线和普通 `\hline`；数字列右对齐，单位写入表头或表注，小数位保持一致。短数字表用 `tabular`，含长文本表用 `tabularx`，跨页记录用 `longtable`。不得把 `\resizebox{\linewidth}{!}{...}` 作为默认解决方案；超宽表应先重设列宽、拆分逻辑或移至附录，不能压缩到不可读字号。

每张图或表都必须形成“正文引入 → 对象 → 现象/比较 → 定量解释 → 结论”的邻接证据单元；不能只写“如图所示”，不能让图表单独占页而没有解释。若用户替换图片，保留旧图、登记新旧文件和替换原因，重新编译并核对 PDF 中实际显示的图片。

论文目录只能保留一个明确的最新交付入口（通常为 `paper/main.tex` 和 `paper/main.pdf`）；旧版移入 `archive/` 或按项目版本隔离，不能让 `main.pdf`、`main_v2.pdf`、`main_final2.pdf` 等多个文件同时充当入口。

## 完整代码附录

完整代码附录是硬性要求，不因篇幅删除。附录必须包含：

1. 与最终交付代码一致的结构与运行关系图；
2. 完整代码文件清单；
3. 每个文件的作用、输入、输出和真实运行命令；
4. 真实核心代码的完整 `lstinputlisting` 展示；
5. `run_all.py` 与逐问入口；
6. 从原始附件到结果、图表和论文的复现说明。

附录代码应从最终交付代码目录直接读取或经过哈希校验复制；不能只写“代码见附件”。参考文献结束后用 `\clearpage` 或等效命令再次分页，附录首页先放结构图和导航，再开始代码正文。
