# MODEL SELECTION RULES

## 强制流程

1. 先校验 `CATALOG_VERSION.json` 的目录版本和文件哈希，再识别题型、二级场景和数据结构（时间序列、截面、图、图像、信号、方程、标签等）。
2. 查询 \`PROBLEM_TO_METHOD_MATRIX.csv\` 和机器目录，获取不超过 3 个候选主模型及不超过 3 个对照。
3. 按题意匹配度、数据适配性、适用前提、解释性、验证性、复现性和主流成熟度排序；S/A 等级只是候选先验，不得替代适配性判断。
5. 至少保留一个透明基线（如线性回归、朴素预测、简单规则或小规模精确解）。
6. 仅当 S/A 方法无法满足题意、约束或误差要求时，才考虑 B/C 级；C 级必须 \`approval_required=true\` 并请求人工确认。
7. 记录适用条件、验证计划、未选方法及放弃理由；模型不适用时退回重新选型，不用复杂算法掩盖题意不清。
8. 目录外方法必须单独标记 \`outside_catalog=true\`，说明主流方法为何不足，人工确认前不得作为主模型。

## 04-cumcm-modeling 输出格式

\`problem_id\`；目录版本；题型和场景；查询到的目录条目；前两名或前三名候选；各候选适配性理由；透明基线；适用条件；验证计划；放弃方法及原因；\`approval_required\`；用户确认记录；锁定主模型。

## 与现有 skill 的接口

- \`03-cumcm-project-start\`：记录 `CATALOG_VERSION.json` 的目录版本及来源哈希/日期。
- \`04-cumcm-modeling\`：先查版本锁定的正向矩阵，再生成前两名或前三名候选，解释适配性后暂停等待用户确认；确认后才锁定主模型。
- \`05-cumcm-coding-visual\`：按 \`minimum_validation\` 生成指标、结果表和图表。
- \`09-cumcm-writing\`：按标准名称、公式、适用条件和证据写正文。
- \`11-cumcm-verify\`：检查目录外方法、选择理由、验证证据和 approval 门。

## 等级与权限

S=教材/竞赛高度常见，可在条件满足时主用；A=成熟对照或主用候选；B=专门/增强方法，默认 optional；C=复杂或创新方法，默认禁止主用且必须人工确认。等级不能替代题意和数据适配性判断；全局人工首选表不参与自动选型，最终模型只在用户确认后锁定。
