# 图表审阅规则

## 审阅目标

数学建模论文中的图片和表格应服务于建模思路、数据理解、结果解释或模型检验。审阅图表时必须同时看图表本体、图题/表题、正文引用、所在章节和前后文结论。

图审不是复述作者说法。必须根据实际图表内容判断它是否支持上下文逻辑；如果图表内容、数据来源或生成过程无法核验，要明确标为“需确认”，并要求作者提供原始数据、图表生成方法、计算脚本或中间结果。

## 反幻觉原则

- 不把图题、正文解释或作者结论直接当作事实。
- 看不到或读不清的图表内容，不猜测；标记为“不可可靠识别”或“需确认”。
- 无法从论文、题目、数据说明或代码中验证的数据合理性，不给“合理/正确”的结论。
- 只能评价已经看到的证据：图表画了什么、正文怎么解释、上下文是否支撑。
- 对需要外部知识才能判断的成熟模型、标准流程或算法图，必要时检索权威论文、教材、官方文档或高质量综述进行对照，并记录来源。
- 外部资料只用于核对流程、变量关系和表达习惯，不替作者补造实验结果、数据或结论。

## 图表审阅记录

每张图和每个关键表格都应建立简短记录，至少包含：

```text
编号：[图/表编号；没有编号则写页码或章节位置]
类型：[数据图/结果图/流程图/模型结构图/算法图/示意图/表格]
本体内容：[实际看到的主要元素、变量、坐标、节点或列名]
上下文位置：[所在章节、图题/表题、正文引用句]
论文声称：[正文用它支撑什么结论]
证据判断：[支持/部分支持/不支持/无法判断]
需确认项：[数据来源、计算口径、原始记录、脚本、读图不清等]
修改建议：[内容修正与美化建议]
```

记录用于生成批注，不一定完整交付给用户；但交付前必须能据此说明每条图表意见来自哪里。

## 必查项目

- 图片是否清晰，分辨率是否足够。
- 图题是否准确，是否能独立说明图片含义。
- 正文是否引用并解释图片。
- 坐标轴名称、单位、刻度、图例是否完整。
- 颜色和线型是否能区分类别，黑白打印时是否仍可辨认。
- 图片是否对应题目问题和模型结果。
- 图片是否存在过度装饰、信息重复或无关内容。
- 图片编号是否连续，与正文引用一致。
- 图中数据是否能从题目、原始数据、模型输出、代码或表格中追溯。
- 图中趋势、排序、极值、结论是否与正文描述一致。
- 表格中的列名、单位、有效数字、统计口径和图中呈现是否一致。
- 图表是否放在最能支撑论证的位置，而不是先出现结论后很久才给证据。

## 按图片类型检查

### 数据分布图

检查是否说明样本范围、变量含义、异常值和分布特征。建议用于数据预处理、问题分析、参数估计前后对比。

若分布图用于支持建模假设或参数选择，必须检查样本量、变量单位、分组方法和异常值处理是否交代清楚。无法核验时要求提供原始数据记录或预处理脚本。

### 趋势图和时间序列图

检查时间轴、单位、平滑方式、预测区间和真实值对比。若有预测，应建议加入误差带或对比基线。

若曲线经过平滑、插值、归一化或筛选，必须要求正文说明处理方法；无法判断处理方式时标为“需确认”。

如果趋势图用于比较不同群体，总量曲线往往受群体规模影响。应检查是否需要补充人均值、客单价、交易次数、归一化指数或置信区间，避免把“人数更多”误判为“价值更高”。

### 散点图和拟合图

检查是否有拟合曲线、相关系数或误差说明。避免只有散点没有结论。

如果正文声称“显著相关”“拟合效果好”或“误差较小”，应检查是否给出相关系数、残差、误差指标或对比基线；没有则建议补充。

### 热力图和空间图

检查颜色条、空间坐标、区域边界、单位和颜色含义。警惕颜色渐变夸大差异。

若颜色映射会影响结论，要求说明色阶范围、归一化方法和缺失区域处理。

### 流程图和模型结构图

检查流程是否对应正文模型步骤，节点命名是否清楚，箭头方向是否准确。适合放在问题分析、模型建立或算法流程处。

必须通读流程图前后文，逐项核对：

- 图中每个关键节点是否在正文中解释。
- 输入、输出和中间变量是否与符号说明一致。
- 箭头方向是否符合算法执行顺序或因果逻辑。
- 分支条件、循环条件、终止条件是否在正文中出现。
- 图中流程是否覆盖题目要求的所有子问题。

如果流程属于已有成熟模型、经典算法或标准业务流程，可检索权威论文、教材、官方文档或高质量综述作对照，检查是否漏掉关键步骤、改变步骤含义或把并列关系画成因果关系。

### 表格转图片

一般不建议把可编辑表格截图成图片。若表格很大，应建议拆分、精简或移至附录。

### 饼图和占比图

当某一类别占比过大、类别过多或小比例标签拥挤时，饼图不利于比较。优先建议改为横向条形图、累计占比图或帕累托图，并在图中保留样本数、占比和分组阈值。

若占比图用于支撑数据结论，必须检查分母口径、分组规则和样本范围是否清楚。

### 结果表格

结果表格应检查列名、单位、有效数字、排序逻辑、最优值标识和正文结论是否一致。若表中结果来自仿真、优化或预测，必须能追溯到模型输出或计算脚本；不能追溯时标为“需确认”，要求作者提供原始输出记录。

若表格展示概率、率、得分或排名，检查数值范围是否合理。例如概率/激活率/转化率通常应在 0%-100% 内；若出现 4318% 这类异常值，应要求回查原始输出、格式转换和小数点。

若结果表中某些类别样本量极少，而正文仍给出一般性管理结论，应提示补充异常类说明、合并策略或稳定性分析。

### 算法对比图表

对算法对比、模型对比、敏感性分析和误差分析，检查是否有统一数据集、统一评价指标和公平对比条件。若只展示有利结果，建议补充基线、误差范围、重复实验次数或失败案例说明。

### 聚类结果表

聚类结果表应检查类别数选择、样本量分布、聚类中心、业务解释和稳定性指标。若类别人数极不均衡，或多个类别的指标向量高度相似，应要求提供 K 值依据、SSE/轮廓系数、初始化方式和重复运行稳定性。

### 关联规则表

关联规则表不能只列“商品 A -> 商品 B”。必须给出支持度、置信度、提升度、最小支持度/置信度阈值、购物篮构造方法和样本时间窗口。否则只能说明“存在候选搭配”，不能支撑促销策略强度。

## 新增图片建议

当正文存在以下情况时，建议新增图片：

- 问题分析文字较长，缺少整体建模路线图。
- 数据预处理步骤复杂，缺少流程图或前后对比图。
- 模型结构包含多个模块，读者难以把握关系。
- 结果只有表格，缺少趋势、排序、空间分布或误差可视化。
- 模型检验只写文字，缺少残差图、敏感性图或对比图。

新增图片批注应写清：

```text
建议新增图片：[图片类型]
建议位置：[放在某段后/某节开头/某结果表后]
图片内容：[应包含哪些变量、坐标、图例或对比]
作用：[帮助评委理解什么结论]
```

## 评价已有图片的批注模板

```text
图片建议：[指出图片问题]
原因：[说明对理解模型或结果的影响]
改法：[给出具体修改，如补单位、重画坐标、增加对比线、提高分辨率]
```

对无法核验的数据图或结果表，使用：

```text
需确认：[目前无法仅凭论文判断该图/表数据是否合理]
原因：[缺少原始数据、计算口径、生成脚本、重复实验记录或统计方法]
请提供：[原始数据记录/图表生成方法/计算脚本/模型输出中间结果]
在提供前：[只能评价表达形式和上下文一致性，不能确认数据结论正确]
```

对流程图、模型图或算法图，使用：

```text
流程图建议：[指出节点、箭头、输入输出或步骤遗漏问题]
上下文依据：[对应正文段落或公式位置]
核对结果：[与正文一致/部分一致/不一致/需外部资料确认]
改法：[调整节点、补充分支、重排顺序、补输入输出或改图题]
```

## 美化建议要求

图表批注必须尽量给出可执行美化建议，而不是只写“优化图片”。优先检查：

- 字号是否与正文协调，打印后是否可读。
- 线宽、点大小、箭头和边框是否过细或过粗。
- 配色是否能区分类别，黑白打印是否仍可辨认。
- 图例是否放在不遮挡数据的位置。
- 坐标轴、单位、色条和注释是否完整。
- 标题是否简洁说明对象、场景和指标。
- 图表宽度是否适合版心，是否被拉伸或压缩。
- 多子图是否统一坐标、尺度、编号和说明。

## 与上下文联动

图片评价必须回答：

- 这张图在当前章节承担什么作用？
- 正文是否解释了图中最重要的现象？
- 图中信息是否支持正文结论？
- 如果删掉这张图，论文论证是否受影响？
- 如果保留，怎样修改能更像竞赛论文中的结果图？

如果以上问题不能回答，应在批注中写明缺失证据，而不是替作者推断。
