## 目标

把用户提供的优秀论文样例整理成可检索的参考库。后续审稿时先给待审论文打标签，再根据标签选择最相关的本地样例，学习其写法、结构、图表组织和表达特征；同时必须联网检索权威外部资料，用于补强本地样例库覆盖不足、核验方法和减少幻觉。

样例库不是语料堆叠。核心产物是：

- 规范文件组织。
- 每篇样例的标签。
- 每篇样例的简短总结。
- 每篇样例的关键词。
- 一个可快速检索的 `index.md`。

当前项目的本地样例库以 `math-modeling-intake/_catalog/manifest.json` 和 `math-modeling-intake/_catalog/sample-index.md` 为生成源。运行 `math-modeling-intake/_tools/build_catalog.py` 后，应把同一份样例索引同步到 `references/exemplars/index.md`，审稿时优先读取这个同步索引。若只需要同步索引，运行 `references/scripts/sync_exemplar_index.py`。

## 存放结构

```text
math-modeling-intake/
├── 题目/
├── 优秀论文/
└── _catalog/
    ├── manifest.json
    ├── sample-index.md
    └── cards/
        └── 2024/
            └── 2024-001.md

.agents/skills/13-cumcm-paper-review/references/exemplars/
├── README.md
├── index.md
└── external/
```

命名建议：

```text
CUMCM-年份-题号-序号
```

示例：`CUMCM-2024-A-01.docx`、`CUMCM-2022-C-03.pdf`。

## 入库流程

用户给出样例、题目或题目信息后：

1. 确认样例文件可打开。
2. 按年份、题号或主题放入 `math-modeling-intake/优秀论文/`。
3. 运行 `math-modeling-intake/_tools/build_catalog.py`，为每篇样例生成 `_catalog/cards/<year>/<sample-id>.md`。
4. 提取标签、简短总结和关键词。
5. 同步更新 `math-modeling-intake/_catalog/sample-index.md` 和 `references/exemplars/index.md`；必要时运行 `references/scripts/sync_exemplar_index.py`。
6. 完成后复核样例索引和卡片：确认没有 `待人工复核`、空标签、空关键词、标题误判或明显 OCR 乱码；图片版样例还要核对 OCR 报告的可读性。
7. 如发现样例体现出新的评价标准，补充到相关审稿规则中，但保持简洁。

## 标签体系

标签使用短词，便于匹配。每篇样例不宜超过 20 个标签。

### 题型标签

- 优化
- 预测
- 评价
- 分类
- 仿真
- 机理建模
- 统计分析
- 图论网络
- 时间序列
- 空间分析
- 多目标决策
- 风险评估

### 方法标签

- 线性规划
- 非线性规划
- 整数规划
- 动态规划
- 层次分析法
- 熵权法
- TOPSIS
- 主成分分析
- 回归分析
- 聚类
- 分类模型
- 时间序列模型
- 灰色预测
- 微分方程
- 蒙特卡洛
- 灵敏度分析
- 机器学习

### 数据标签

- 表格数据
- 时间序列
- 空间地理
- 图像数据
- 文本数据
- 多源数据
- 缺失数据
- 小样本
- 大规模数据
- 公开数据
- 自建指标

### 写法标签

- 摘要定量清晰
- 问题分析强
- 模型路线清晰
- 公式解释充分
- 结果解释充分
- 检验完整
- 图表组织好
- 附录规范
- 语言凝练
- 结构层次清楚

### 图表标签

- 流程图
- 模型结构图
- 数据分布图
- 趋势图
- 热力图
- 空间图
- 对比图
- 敏感性分析图
- 误差图
- 排名表
- 指标体系表

### 风险标签

用于提醒不要盲目学习：

- 题型不匹配
- 方法较复杂
- 图表依赖强
- 数据条件特殊
- 摘要不可学
- 格式不可学
- 结论表达弱

## 样例卡片格式

每篇样例生成一个 `.card.md`：

```markdown
# 样例编号：[CUMCM-年份-题号-序号]

- 文件：[相对路径]
- 题目/方向：[简短描述]
- 题型标签：[标签列表]
- 方法标签：[标签列表]
- 数据标签：[标签列表]
- 写法标签：[标签列表]
- 图表标签：[标签列表]
- 风险标签：[标签列表]
- 适合参考：[这篇样例最值得学什么]
- 不适合参考：[哪些地方不应照搬]
- 简短总结：[100-200 字，概括问题、方法、结构、亮点]
- 关键词：[8-15 个关键词]
```

卡片不保存长段原文。

## 索引格式

`references/exemplars/index.md` 使用表格，并保留匹配样例的卡片路径：

```markdown
# 样例索引

| 编号 | 年份 | 来源类型 | 标题 | 标签 | 关键词 | 卡片 |
|---|---:|---|---|---|---|---|
| 2024-001 | 2024 | pdf | 示例标题 | 优化, 图表密集 | 优化模型, 结果解释 | math-modeling-intake/_catalog/cards/2024/2024-001.md |
```

索引用于首轮筛选，避免读取全部样例。

## 整理后复核

每次新增、替换或批量整理样例后，必须先复核再进入审稿或等待下一步：

1. 刷新样例索引、样例卡片和 manifest。
2. 统计样例总数、本轮新增数量、各年份数量和文本状态。
3. 检查是否仍有 `待人工复核`、`scan-like`、`image-folder`、空标签或空关键词。
4. 对本轮新增样例逐篇抽查标题、摘要、关键词和标签；图片版样例同时检查 OCR 侧写和 `readable` 判定。
5. 对可读但尚未替换的文件，确认已放入待替换目录并写入报告。
6. 对不可读或不稳定样例，不猜测标签；保留复核标记并告诉用户需要更清晰版本、人工阅读或放弃。

## 审稿时的匹配策略

给待审论文打标签后：

1. 题型标签匹配优先级最高。
2. 方法标签次之。
3. 数据标签用于判断可借鉴程度。
4. 写法标签用于选择表达和组织参考。
5. 图表标签用于选择图表改进参考。
6. 风险标签用于排除不适合参考的样例。

默认筛选 5-8 篇候选样例，并精读 3-5 篇核心样例或样例卡片；如果本地样例库实际不足 5 篇，保留全部可用候选并说明局限。不要只凭最高匹配分把参考样例压缩到过少数量。

优先运行：

```powershell
python -X utf8 .agents\skills\13-cumcm-paper-review\scripts\review_case_tool.py match-exemplars --case-dir math-modeling-review-cases\CASE_ID --labels "优化,图表密集" --methods "线性规划,敏感性分析" --topic "生产调度优化"
```

输出：

- `work/exemplar_match.json`
- `work/exemplar_match_report.md`

匹配器使用保守、可解释的规则：题型和方法权重最高，数据、图表和写法标签用于补充，风险标签用于降权，关键词和主题词只做辅助。若存在长期反馈日志，匹配器会读取权威点评记录作为轻量校准提示；这些反馈用于解释和小幅排序，不直接把单个点评变成固定评分标准。最终仍需人工判断核心样例是否真适合当前题目。

## 外部权威参考

正式审稿必须检索网络上的权威外部资料，不以本地样例是否匹配为条件。范围不限于数学建模竞赛论文，也包括学术论文、综述论文、方法论文、教材级资料、官方文档和高质量案例研究。

硬性要求：

- 每次正式审稿都必须执行外部检索并记录检索日期。
- 至少形成 3-5 条候选外部资料记录；最终使用 2-4 条最可靠、最相关资料。
- 如果联网能力不可用，必须在交付中明确说明“外部检索未完成”，并把该项列为审稿可靠性限制。
- 快速试跑也必须执行外部检索；如时间或工具受限，至少记录已检索来源和未完成限制，不能把未检索说成已检索。

检索规则：

- 优先使用当前可用的联网检索能力；如有 `agent-reach`，可用于搜索公开网页、论文页面、GitHub 或相关平台。
- 优先运行 `scripts/review_case_tool.py search-references`，把检索词、候选资料、可信度初筛和参考卡片草稿保存到当前 case 的 `work/` 目录。
- 优先检索高可信来源：竞赛官网公开优秀论文、学校/课程公开优秀论文、期刊论文、会议论文、arXiv、CNKI/万方可访问摘要页、Google Scholar 可索引页面、教材/官方文档等。
- 检索关键词应由待审论文标签生成，组合题型、方法、数据类型和应用领域。
- 不使用无来源、转载链条不明、无法确认作者/机构或明显营销化的材料作为依据。
- 不因材料表述“看起来合理”就采信；必须核对来源可信度、方法适配性、与题目和待审论文上下文的一致性。
- 数模论文用于学习竞赛结构、摘要写法、模型叙述和附录组织；学术资料用于核验方法流程、指标定义、图表表达和结果讨论。

外部参考卡片保存到：

```text
references/exemplars/external/
```

命名建议：

```text
EXT-年份-来源缩写-序号.card.md
```

外部参考卡片格式：

```markdown
# 外部参考编号：[EXT-年份-来源-序号]

- 来源类型：[数模论文/学术论文/综述/方法论文/案例研究]
- 题名：
- 作者/机构：
- 年份：
- 链接：
- 检索日期：
- 可信度：[高/中/低]
- 题型标签：
- 方法标签：
- 数据标签：
- 写法标签：
- 图表标签：
- 适合参考：
- 不适合参考：
- 摘要级总结：
- 关键词：
```

版权和使用边界：

- 不复制论文正文、图表、数据或结论。
- 不把外部论文内容改写成待审论文内容。
- 只提取摘要级总结、结构特征、方法组织方式、图表表达策略和评价标准。
- 最终审稿建议必须回到用户论文自身的问题，不能要求作者照搬外部论文。

## 权威点评反馈接口

若用户提供权威点评视频、文档、网页、课程讲义、教师评语或赛后点评，先把内容整理成反馈记录，再用于长期校准样例匹配系统。不要把视频/文档点评直接变成固定权重。

处理规则：

- 优先运行 `make-feedback-template` 生成草稿，再用 `build-feedback` 转为结构化 JSON 和 JSONL 学习日志。
- 记录来源类型、标题、链接或本地路径、点评者/机构、可信度、日期、适用题型和方法标签。
- 分开记录正向信号、负向信号、适用章节、涉及样例、对评分权重的启发和适用边界。
- 权威点评只作为反馈信号；后续评分器应综合多次反馈，不因单个视频或单篇文档立刻大幅改权重。
- 具体反馈日志默认保存在 `math-modeling-review-cases/_learning/`，不随开源 skill 提交。

## 节省 token 规则

- 审稿默认只读 `index.md` 和匹配样例的 `.card.md`。
- 不要一次性读取所有样例全文。
- 不要把样例长段内容复制进审阅结果。
- 若需要学习具体写法，只读取相关章节或页面。
- 每次审稿只保留与当前论文标签直接相关的样例信息。
- 外部参考默认只读参考卡片；除非需要核验来源或学习具体结构，不打开全文。
