# 高教杯数学建模论文终审

## 阶段合同（机器接口）

- phase_id: 13-cumcm-paper-review；display_name: 国赛论文终审；owner_agent: paper-review-agent。
- entry_conditions: 11 verify PASS；若有 DOCX，必须已完成 12 渲染审计；最终 PDF/DOCX 路径和哈希已锁定。
- inputs: 最终 PDF/DOCX、题面、评分要求、结果索引、模板锁、验收报告和可选优秀论文样例。
- outputs: reports/PAPER_REVIEW_REPORT.md、PAPER_REVIEW_ISSUES.csv、可选同格式批注副本。
- exit_conditions: 结构、行文、视觉、图表、引用和复现风险均有分级结论；phase_result=REVIEWED。
- failure_return: 只返回责任阶段和复核项；不直接修改模型、结果、正文或 PDF canonical。
- writable_paths: reports/PAPER_REVIEW_REPORT.md、reports/PAPER_REVIEW_ISSUES.csv、用户授权的 review/ 副本。
- read_only_paths: 最终交付物、题面、代码、结果、模板、验收报告和样例库。
- invalidates: 终审发现的事实/结构/版式问题使相应 owner 阶段及 11 verify 失效。
- user_gate: false；用户若要求批注副本，另行明确授权。
## 本地多智能体合同
- owner_agent：paper-review-agent；
- 只在全部要求交付物完成后作为最终独立审阅；
- 默认只读，不覆盖 canonical 文件；
- 输出 PASS、REVISE 或 BLOCKED，并按问题类型回流；
- 退出状态：PASS、REVISE 或 BLOCKED。

用于审阅已完成或接近完成的数学建模论文。输入通常是 `.docx` 或 `.pdf` 文件，输出应是与输入格式一致的新文件，并只在需要改动的位置加入明显高亮批注。

## 触发场景

当用户要求以下任务时使用本 skill：

- 审阅、评价、批改数学建模论文
- 按国赛标准检查论文格式和内容
- 润色数学建模论文措辞、语病、标点
- 检查摘要、模型假设、模型建立、求解、检验、评价等章节
- 评价论文中的图、表、流程图、算法图、结果图
- 建议新增图片、表格或可视化位置

## 用户引导

触发后先用一句话说明接下来会建立 case 目录并保护原文件，再检查用户是否已经提供三类核心材料：

- 待审论文：必需，支持 `.docx` 或 `.pdf`。
- 题目文件：强烈建议提供，用于判断是否完整回答子问题。
- 评分标准、`format` 或学校模板：建议提供；若没有，则使用默认国赛标准。

优秀论文样例是增强材料，不是启动条件。若用户没有提供优秀论文，继续按“默认国赛标准 + 当次题目/评分标准 + 权威外部资料检索”审稿，并说明本地样例对标能力会降低。不要让新用户误以为必须先整理样例库才能使用。

如果材料不全，用短句说明影响并给出下一步：

- 缺论文：直接要求用户提供待审 `.docx` 或 `.pdf`。
- 缺题目：可先做格式、语言、结构和图表表达审阅；题意完整性判断需要题目文件。
- 缺评分标准：按默认国赛标准审阅；用户之后补充评分细则时，可再复核。
- 缺优秀论文：继续审稿，同时联网找权威资料；本地样例匹配报告中标注“无可用本地样例”。
- 缺联网能力：先生成检索词和待查资料清单，要求用户开启联网能力、配置检索工具或提供权威资料链接。

## 进度提示

处理细活时，用一句简短、事实性的中文提示告诉用户正在做什么。提示应说明当前阶段和目的，不要复述用户问题，不要使用“好的”“明白了”“让我来”等开场套话，不要夸赞。

推荐提示：

- “我先把题目和论文复制到本次 case 目录，避免改动原文件。”
- “我正在抽取正文、图表和版式信息，用来定位后续批注。”
- “我正在生成图表清单，先防止漏审图片、表格和关键结果图。”
- “我正在给待审论文打标签，用于匹配样例和生成外部检索词。”
- “我正在匹配本地样例；没有合适样例时会继续走外部权威资料检索。”
- “我正在检索权威资料，并记录来源、用途和检索日期。”
- “我正在把审稿意见整理成结构化批注，准备写回原格式文件。”
- “我正在渲染检查输出文件，确认标注可见且没有遮挡正文。”

这些提示只在阶段切换、长时间处理或用户可能等待时发送；不要为每个小文件或每条批注刷屏。

## 输入与输出

### 输入

- 单个 `.docx` 或 `.pdf` 论文文件。
- 可选：用户提供的具体竞赛题目、评分细则、学校模板、往年优秀论文样例。
- 可选：已整理的样例库索引或外部参考索引，用于按标签选择参考论文。
- 可选：一个包含“题目”和“优秀论文”的总文件夹。

### 输出

- 生成一个新的同格式文件：
  - `.docx` 输入输出 `.docx`
  - `.pdf` 输入输出 `.pdf`
- 新文件命名建议：`原文件名_reviewed.docx` 或 `原文件名_reviewed.pdf`
- 试用或正式审稿时，先在项目内创建或复用 `math-modeling-review-cases/<case-id>/`，分别保存题目原件、论文原件、审阅输出和过程材料。
- 每次审稿生成 `work/reference_report.md`，列出本地样例、外部资料、资料支撑的建议类型和仍需用户确认的数据项。
- 只在需要修改、提醒或建议的位置添加高亮批注。
- 不直接覆盖原文件。
- 批注应与原文保持视觉间隔，避免挤压或遮挡正文。

如文件格式或工具限制导致无法可靠写回同格式文件，先说明限制，再提供最接近的可执行方案，例如生成带页码和位置说明的审阅报告，或请求用户提供 `.docx` 源文件。

## 工具选择

- 稳定执行步骤优先使用 `scripts/review_case_tool.py`，不要把一次性案例脚本继续散落在 `math-modeling-review-cases/<case-id>/work/`。审稿判断和批注内容先整理为 `work/issues.json`，再用脚本完成写回、提示清单和验证。
- 修改脚本后运行 `scripts/review_case_tool.py run-regression-tests`，确认 PDF 标注、DOCX 高亮、图审 JSON 和参考来源报告没有回归。
- `.docx`：优先使用文档处理能力读取、编辑、批注、渲染验证。
- `.pdf`：优先使用 PDF 处理能力读取、渲染页面、检查版式和图片；若需要可编辑批注，生成带批注的新 PDF。
- PDF 审阅不要只依赖阅读器批注功能；为兼容 WPS 等阅读器，必须同时输出按页码和原文定位的通用文本提示清单，必要时把提示页直接追加到 PDF 中。
- 如果用户要求在原文中标出定位，或发现 WPS/阅读器看不到批注，则不要只使用 PDF annotation 对象；应把定位标记直接写入 PDF 页面内容。优先使用不遮挡正文的永久描边框、下划线和编号，编号与追加提示页或文本清单一一对应。
- 图表：必须读取页面渲染或嵌入图片内容，建立“图表本体-图题/表题-正文引用-上下文段落-结论”的证据链后再评价；不能只按作者文字描述接受图表含义。
- 国赛增强审查：按 `references/cumcm-enhanced-criteria.md` 检查正文 25-30 页、摘要不少于 700 字、误差/灵敏度/稳健性三类检验和图片是否足以支撑模型与结果。公式、表格、参考文献和多模型/多场景对比按题目合理性判断，不设机械数量门槛。
- AI 痕迹：可审查模板化套话、风格突变、无依据的公式/结论、不可检索引用和数字/代码/图表不一致等风险信号；不得凭文风直接认定 AI 生成率或违规，不默认检查 AI 工具详情和 AI 声明一致性。
- 流程图工具：不要求 Graphviz；只检查流程图逻辑、可读性、尺寸、箭头和正文一致性。
- 图表清单：正式图审前先运行 `scripts/review_case_tool.py build-figure-inventory`，生成 `work/figure_inventory.json` 和 `work/figure_inventory.md`，用于防止漏审图题、表题、内嵌图片和关键结果表；清单只做定位和待审状态，不替代图表合理性判断。
- 图表数据合理性：当图、表中的数据来源、计算过程、坐标含义或统计口径无法从论文和题目中验证时，不要猜测合理性；必须标为“需确认”，并要求用户提供图表数据取得方法、原始数据记录、计算脚本或中间结果。
- 流程图/模型图：必须通读前后文，检查节点顺序、箭头方向、输入输出、约束条件和算法步骤是否与正文一致；对已有成熟模型或标准流程，必要时检索权威论文或教材级资料进行对照，并记录来源。
- 图表美化：图审意见必须同时给出可执行的美化建议，包括清晰度、字号、线宽、配色、图例、坐标轴、单位、图题、黑白打印可辨性和版面位置。
- 样例：审稿前先给待审论文打标签，优先运行 `scripts/review_case_tool.py match-exemplars` 从样例索引中筛选 5-8 篇候选样例，精读 3-5 篇核心样例或卡片作为写法、结构和图表组织参考；若本地样例库规模不足，保留全部可用候选并说明局限。
- 外部参考：正式审稿必须联网检索相关数模论文、学术论文、教材级资料、官方文档或高质量综述；优先选择竞赛官网、学校公开优秀论文、期刊/会议论文、预印本平台、教材/官方文档等可追溯来源。只提取题名、来源、检索日期、标签、摘要级总结、方法、评价标准和写法特征，不复制正文，不照搬结论。
- 权威点评反馈：用户提供权威点评视频、文档、网页或教师评语时，先整理为反馈记录，用于后续样例匹配权重校准；不要把单个点评直接写死成评分标准。
- 总文件夹：先区分“题目/优秀论文”，再按年份和题型递归处理；评分标准 `format` 必读，题目文件只需读取一个可读格式即可。
- 图片版论文：若 OCR 能稳定读取标题、摘要、关键词和主要结构，就自动生成标签、关键词、总结和样例卡片；若 OCR 不达标，明确标记不可自动读取，并要求用户人工阅读、提供更清晰版本或放弃该样例。
- 样例整理完成后必须复核：刷新样例索引和 manifest，检查是否仍有 `待人工复核`、`scan-like`、`image-folder` 或兜底标签，抽查 OCR 报告和样例卡片，确认标题、摘要、关键词和标签没有明显误判。

## 扫描件分流

当输入文件疑似扫描件时，先不要按正文可提取文件处理，按下面顺序分流：

1. 先判断是否存在水印。
2. 如果有水印，先要求用户去除水印并重新提供文件。
3. 去除水印后，再询问是否按图像版论文处理。
4. 如果用户选择按图像版处理，就按图像版论文流程继续：渲染页面、按页阅读、建样例卡片、打标签、总结和关键词提取。
5. 如果用户不想按图像版处理，要求用户提供可直接读取的版本，或者放弃这篇论文。
6. 如果文件本身没有水印，则直接进入“是否按图像版处理”的询问步骤。
7. 只有在用户确认按图像版处理后，才继续后续的视觉阅读和卡片化整理。

批量处理已去水印扫描论文时，按 `references/scanned-paper-ocr.md` 执行：先 OCR 侧写并判定可读性，只替换通过检查的文件，遇到文件锁则写入待替换目录并报告。

## 审阅原则

- 按国赛论文表达习惯评价，不按普通课程论文或科普文章标准替代。
- 关注“能否让评委快速理解模型、方法、结果和创新点”。
- 审阅不能只看语言和格式；必须检查题意是否完整回答、模型是否过度简化、约束是否有来源、时间/空间/阶段维度是否被错误聚合、参数是否被不当平均、结果是否有基线和本题合理性证据、结论是否超出证据。
- 修改建议要具体到位置和原因，避免泛泛而谈。
- 若用户提供批注或要求逐条落实，建立 `work/ANNOTATION_TRACKER.csv`，至少记录批注编号、页码/定位、原批注、涉及文件、修改动作、修改状态和验证结果；不得只落实最新批注而遗漏已有意见。
- 对原文可接受但可优化的地方，用建议语气；对明显错误、格式不合规、逻辑断裂处，用明确问题语气。
- 不凭空添加实验结果、数值结论或参考文献。
- 对数学符号、变量、单位、图表编号、章节编号的一致性保持敏感。
- 样例只用于学习写法、结构、图表组织和表达特征，不复制具体内容、数据、图表或结论。
- 网络论文和学术论文是正式审稿的必备外部核验材料，必须记录来源和检索日期；优先选择权威、可访问、与当前题型高度相关的材料。不能因资料表述“看起来合理”就采信，至少要核对来源可信度、方法适配性、与题目/论文上下文的一致性；无法确认时标为“需确认”。
- jpg 图片形式的论文视为图像版论文，先按页或按文件顺序读取，再结合 OCR/视觉判断建立样例卡片。能自动读取文本时直接按文本侧写生成标签和关键词；不能自动读取时不要猜测内容，标记为 `待人工复核` 并说明需要用户处理。

## 处理完成前检查

交付前必须确认：

- 输出文件存在，且未覆盖原文。
- 输出格式与输入格式一致。
- 题目、论文原件和审阅后文件已放入本次 `math-modeling-review-cases/<case-id>/` 对应子目录。
- 批注或高亮只出现在需要改动的位置。
- 批注与原文有间隔，不遮挡正文。
- 图表评价已经结合图表本体、图题/表题、正文引用和上下文，不仅复述作者文字。
- 对数据图和结果表，已判断数据来源、计算口径和结论支撑关系；无法验证时已标为“需确认”，并要求用户提供原始数据、生成方法或脚本。
- 对流程图、算法图和模型结构图，已核对前后文逻辑；涉及成熟模型或标准流程时，已在必要范围内对照权威资料。
- 图表审阅已包含美化建议。
- 已为待审论文生成标签，并说明参考了哪些本地样例、外部资料和选择理由；如没有可用本地样例，说明本地样例局限，但仍需完成权威外部检索。
- 已生成 `work/reference_report.md`，并列明本地读了哪些样例、外部找了哪些资料、每个资料支撑了什么建议、哪些判断仍需用户提供数据确认。
- 已按题目/优秀论文总文件夹的年份结构整理过输入。
- 若执行了样例整理、OCR 入库或批量替换，已刷新索引并完成整理后复核；仍不可读或被占用的文件已列出。
- 至少检查过摘要、模型假设、模型建立、模型求解、结果分析、模型检验、优缺点评价、参考文献和附录。
- 已按用户确认的增强标准检查正文篇幅、摘要下限、三类模型检验、图片充分性和 AI 痕迹风险，并将题目相关数量项目按“合理/不足/过度”说明理由。
- 对 `.docx` 和 `.pdf`，尽可能渲染页面进行视觉检查；PDF 交付前优先运行 `verify-pdf` 并查看 `work/render_acceptance.json`，确认关键页非空、彩色定位标记可见、追加提示页可读。
